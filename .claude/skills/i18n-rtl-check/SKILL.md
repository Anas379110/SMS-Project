# التحقق من i18n وRTL/LTR

## متى تُستدعى
عند الانتهاء من أي مكوّن أو صفحة UI جديدة، قبل اعتبارها "Done" (Definition of Done بـ CLAUDE.md).

## خطوات التنفيذ
1. ابحث بالملف عن أي نص عربي/إنجليزي مكتوب مباشرة بالـ JSX/TSX (خارج دوال next-intl مثل `t()`)
2. تحقق أن كل نص جديد أُضيف لكل من `messages/ar.json` و`messages/en.json` بنفس المفتاح
3. افحص المكوّن بصرياً (أو بمنطق التصميم) بكلا الاتجاهين: هل الأيقونات الموجّهة (أسهم، سهم "رجوع") تنعكس صحيحاً بـ RTL؟
4. تحقق أن طول النص العربي (عادة أطول من الإنجليزي بنفس المعنى) لا يكسر التخطيط
5. تحقق أن التواريخ والأرقام تُعرض بالتنسيق المناسب لكل لغة

## القواعد
- أي نص Hardcoded يُعتبر فشلاً بـ Definition of Done — لا استثناءات (حتى نصوص placeholder أو رسائل خطأ مؤقتة)
- لا يكفي اختبار اتجاه واحد فقط قبل الدمج (Merge)

## الناتج المتوقع
تأكيد صريح: "لا نص Hardcoded، تم اختبار RTL/LTR، الملفان ar.json/en.json محدّثان" — أو قائمة بالمشاكل المكتشفة قبل المتابعة.
