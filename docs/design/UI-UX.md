# UI-UX.md

النطاق: MLP الأول — 5 أدوار (Admin, Teacher, Parent, Student, Accountant)، عربي/إنجليزي، RTL/LTR كامل. بما أن النموذج **MLP** (لا MVP)، الشاشات القليلة المتاحة يجب أن تكون **مصقولة بالكامل**، لا مجرد وظيفية.

## 1. Personas (مختصرة — التفصيل الكامل بـ PROJECT.md/SRS.md)
- **Admin:** يحتاج نظرة شاملة سريعة، لا تفاصيل مربكة بالشاشة الرئيسية
- **Teacher:** يحتاج سرعة تنفيذ (تسجيل حضور/درجات) — أقل عدد نقرات ممكن
- **Parent:** يحتاج وضوحاً فورياً بلا مصطلحات تقنية — "هل ابني بخير؟ هل عليّ شيء؟"
- **Accountant:** يحتاج دقة أرقام وتقارير واضحة، لا تصميم "جميل" على حساب الوظيفة
- **Student:** واجهة مبسّطة جداً (حسب عمر الطالب، قد تحتاج إشراف ولي أمر لحسابات الأصغر سناً)

## 2. User Flows الأساسية (Must)

### Flow: تسجيل الدخول
```
زيارة الدومين الخاص بالمدرسة
→ عرض شعار/ألوان المدرسة تلقائياً (Branding مُحمّل من school-settings)
→ إدخال بريد/كلمة مرور
→ توجيه للوحة الرئيسية حسب الدور
```

### Flow: المعلم يسجل الحضور (أهم Flow بالنظام — يجب أن يكون الأسرع)
```
لوحة المعلم → اختيار الفصل → شاشة الحضور (كل الطلاب "حاضر" افتراضياً)
→ تعديل الاستثناءات فقط (نقرة واحدة لكل تغيير) → حفظ → تأكيد بصري فوري
```

### Flow: ولي الأمر يتابع ابنه
```
لوحة ولي الأمر → اختيار الابن (إن كان أكثر من طالب) → تبويبات: الحضور / الدرجات / الفواتير
→ كل تبويب يعرض آخر التحديثات أولاً (Recency-first)
```

### Flow: المحاسب يصدر فاتورة
```
لوحة المحاسب → الطلاب → اختيار طالب/فصل كامل → اختيار بند الرسوم
→ معاينة الفاتورة قبل الإصدار → تأكيد → إصدار (+ إشعار تلقائي لولي الأمر)
```

## 3. الشاشات الأساسية (Must Screens)
| الشاشة | الأدوار |
|---|---|
| تسجيل الدخول | الكل |
| لوحة رئيسية (تختلف المحتوى حسب الدور) | الكل |
| قائمة/تفاصيل الطلاب | Admin, Teacher |
| تسجيل الحضور | Teacher |
| رصد الدرجات | Teacher |
| كشف حضور/درجات طالب | Admin, Parent, Student |
| الجدول الدراسي | الكل (عرض) |
| إعدادات المدرسة (Branding) | Admin |
| الفواتير والدفعات | Admin, Accountant, Parent |
| إعدادات الحساب الشخصي | الكل |

## 4. التنقل (Navigation)
- Sidebar ثابت بالشاشات الكبيرة، Bottom Navigation بالموبايل (Mobile-first لأن أولياء الأمور غالباً يستخدمون الهاتف)
- عناصر القائمة تختلف تلقائياً حسب دور المستخدم — لا عناصر معطّلة/رمادية بلا فائدة

## 5. Wireframes → Mockups → Prototype
- **Wireframes:** رسم يدوي/Low-Fi لكل شاشة Must قبل أي كود (Figma كافٍ)
- **Mockups:** تصميم عالي الدقة بعد اعتماد Wireframes — يشمل حالة RTL وLTR لكل شاشة (وليس شاشة واحدة يُفترض أنها تُعكس تلقائياً بلا اختبار فعلي)
- **Prototype:** نموذج Figma تفاعلي لأهم Flow (تسجيل الحضور) على الأقل قبل البدء بالكود الفعلي — تجربة سريعة يجب أن "تُحس" سريعة قبل قياسها بالكود

## 6. Design System (مبسّط لهذه المرحلة)
- لوحة ألوان أساسية محايدة (تُخصص فوق شعار كل مدرسة لاحقاً — لا تتعارض ألوان المدرسة مع وضوح القراءة)
- Typography: خط يدعم العربية بجودة عالية (مثال: Cairo/Tajawal للعربي، Inter للإنجليزي) — لا خط واحد يُفترض أنه يخدم اللغتين بجودة متساوية
- مكونات shadcn/ui كأساس، تُخصص بالحد الأدنى اللازم

## 7. حالات الواجهة الإلزامية (كل شاشة Must تحتاجها الثلاثة)
- **Loading State:** Skeleton بسيط، لا Spinner فارغ بدون سياق
- **Empty State:** رسالة واضحة (مثال: "لا يوجد طلاب بهذا الفصل بعد" + زر إضافة إن كان الدور مناسباً) — ليس شاشة فارغة صامتة
- **Error State:** رسالة بلغة بشرية (لا Stack Trace أبداً)، مثال: "تعذّر حفظ الحضور، تحقق من الاتصال وحاول مجدداً" بدل رمز خطأ تقني

## 8. الإتاحة (Accessibility)
- معيار WCAG 2.1 AA كحد أدنى المستهدف (قد تُوثّق استثناءات دقيقة بضغط وقت 3 أشهر، لا تُخفى)
- نسبة تباين ألوان ≥ 4.5:1 حتى مع ألوان علامة تجارية مخصصة لكل مدرسة (قيد يُفرض بمنطق التحقق، لا يُترك لاختيار المدرسة الحر بالكامل)
- أزرار اللمس ≥ 44px (مهم خصوصاً لواجهة المعلم بالحضور — استخدام سريع بالهاتف أثناء الحصة)

## 9. Responsive Design
- **Mobile First** فعلياً لا شعارياً — أولياء الأمور والمعلمون يستخدمون الهاتف أكثر من الديسكتوب غالباً
- اختبار على 320px / 768px / 1440px كحد أدنى قبل اعتبار أي شاشة مكتملة

## 10. التوطين (Localization) وRTL/LTR
- **لا نص Hardcoded بالكود إطلاقاً** — كل نص عبر next-intl من اليوم الأول (راجع DECISIONS.md)
- اختبار كل شاشة Must بكلا الاتجاهين فعلياً (لا افتراض أن Tailwind `dir` يحل كل شيء تلقائياً — الأيقونات الموجّهة اتجاهياً [مثل الأسهم] تحتاج معالجة يدوية)
- طول النص يختلف بين العربي والإنجليزي — لا تصميم يفترض طول ثابت بالأزرار/العناوين
